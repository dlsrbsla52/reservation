## 3. DB 스키마

### 최종 상태

```sql
-- stop.stop
x_crd  NUMERIC(10, 7) NOT NULL,  -- 경도 WGS84
y_crd  NUMERIC(10, 7) NOT NULL,  -- 위도 WGS84

CREATE INDEX idx_stop_coord ON stop.stop (y_crd, x_crd);

-- stop.stop_update_history (nullable)
old_x_crd / new_x_crd / old_y_crd / new_y_crd  NUMERIC(10, 7)
```

`NUMERIC(10, 7)` — 정수부 3자리(경도 최대 180), 소수부 7자리(약 1.1cm 해상도).

### changeSet 구성 (`V004`)

| id | 역할 |
|----|------|
| `V004-1` | **사전 검증.** 숫자로 파싱 불가능한 행이 있으면 `HALT`로 배포 중단 |
| `V004-2` | `stop.stop` 좌표 타입 변경 (rollback 정의 포함) |
| `V004-3` | `stop_update_history` 좌표 타입 변경 |
| `V004-4` | `idx_stop_coord` 생성 (`indexExists` preCondition으로 멱등) |
| `V004-5` | 컬럼 주석 갱신 |

> PostgreSQL은 `varchar → numeric` 암묵 캐스팅을 허용하지 않는다.
> Liquibase `modifyDataType`으로는 실패하므로 **`USING` 절을 포함한 raw `<sql>`** 을 썼다.
> 이력 테이블은 nullable이라 `NULLIF(TRIM(COALESCE(col,'')), '')::NUMERIC(10,7)`으로 빈 값을 NULL로 흡수한다.

## 4. 반드시 지켜야 할 불변식

이 절이 이 문서의 핵심이다. 아래는 모두 **실제로 밟았거나 밟기 직전이었던 함정**이다.

### 4.1 좌표 변환은 반드시 `Coordinate`를 경유한다

`String` ↔ `BigDecimal` 변환을 직접 하지 말 것. `support/Coordinate.kt`가 범위 검증과 scale 정규화를 함께 수행한다.

```kotlin
Coordinate.parseLongitude(raw)      // 실패 시 400 BusinessException — 수기 등록 경로
Coordinate.parseOrNullLongitude(raw) // 실패 시 null — 일괄 적재 경로(배치 중단 방지)
Coordinate.normalize(bigDecimal)     // scale 7 고정
Coordinate.isSame(a, b)              // 값 비교
```

### 4.2 좌표 비교에 `==` / `equals`를 쓰지 말 것

**`BigDecimal.equals`는 scale까지 비교한다.** `BigDecimal("37.0") == BigDecimal("37.0000000")`은 `false`다.

DB에서 읽은 값은 scale 7로 고정되지만 새로 파싱한 값은 입력 표기에 따라 scale이 달라진다. 그대로 비교하면 **값이 같은데도 변경으로 오탐지**되어, 공공 API 재동기화마다 전체 11,000건에 불필요한 UPDATE와 이력 행이 쌓인다.

```kotlin
// 금지
if (xCrd != newXCrd) { ... }

// 필수
if (!Coordinate.isSame(xCrd, newXCrd)) { ... }   // 내부적으로 compareTo
```

애초에 `double precision`이 아니라 `numeric`을 택한 이유도 같은 맥락이다. 부동소수점은 파싱 오차로 동일한 오탐지를 일으킨다. 회귀 방지는 `CoordinateTest.isSame은_scale_차이를_무시한다`와 `StopUpdateHistoryEntityTest.applyUpdate_좌표_표기만_다르고_값이_같으면_null_반환`이 담당한다.

### 4.3 대문자로 시작하는 약어 프로퍼티는 직렬화명이 깨진다

`val xCrd`의 게터는 `getXCrd()`이고, Jackson 기본 네이밍은 게터명 앞쪽 연속 대문자를 소문자로 바꾼다 → **직렬화명이 `xcrd`가 된다.**

이 작업 전 실제 응답은 다음과 같았다.

```json
{"id":"...","stopId":"11833","stopName":"중계역","nodeId":"...","xcrd":"127.0627647","ycrd":"37.6472686"}
```

동시에 `@param:Schema`를 쓰면 springdoc이 생성자 파라미터에서만 스키마를 인식해 OpenAPI에 `xCrd`가 `writeOnly: true`로 문서화된다. **문서상 필드와 실제 필드가 다르고, 문서상 필드는 응답에서 제외된 것으로 표기**되는 상태였다.

```kotlin
// 필수 패턴
@get:JsonProperty("xCrd")
@get:Schema(description = "경도 WGS84 (XCRD)", example = "127.0627647")
val xCrd: String,
```

새 DTO에 `xCrd`, `yCrd`, `xPos` 같은 이름을 쓸 때 같은 함정에 빠진다. **지도용 DTO가 `lat`/`lng`를 쓰는 것도 이 문제의 원천 회피가 목적**이다(`getLat()` → `lat`, 깨지지 않음).

회귀 방지: `BusStopResponseSerializationTest`, `StopInfoDeserializationTest`.

### 4.4 KDoc 안에 `/**` 문자열을 쓰지 말 것

**Kotlin은 블록 주석이 중첩된다.** KDoc에 URL 패턴 `` `/api/v1/stop/**` `` 를 쓰면 `stop/` + `**`가 `/*`로 읽혀 내부 주석이 열리고, 바깥 `*/`가 그것을 닫아버려 `Syntax error: Unclosed comment`가 난다.

```kotlin
// 컴파일 실패
/** 게이트웨이는 `/api/v1/stop/**` 를 8182로 라우팅한다 */

// 정상
/** 게이트웨이는 `/api/v1/stop` 하위 전체를 8182로 라우팅한다 */
```

### 4.5 지도 슬라이스와 커맨드 경로를 섞지 말 것

`map/` 패키지는 `StopService` / `StopRepository`를 재사용하지 않는다. 두 경로의 요구가 정반대이기 때문이다.

- 커맨드 경로 — 가드, 변경 이력, 단가 결합 등 **정합성** 우선
- 지도 경로 — 인덱스 범위 스캔 1회로 끝나는 **응답 속도와 페이로드 크기** 우선

`StopMapRepository`는 Exposed DAO로 wrap하지 않고 4개 컬럼만 projection해 곧바로 DTO로 매핑한다. DAO를 쓰면 안 쓰는 컬럼까지 읽고 영속성 컨텍스트에 수천 건이 적재된다.

**지도 응답에 단가(`StopPrice`)를 붙이지 말 것.** 마커 표시에 불필요하고, 수천 건 조회에 단가 결합을 더하면 경량 DTO를 만든 이유가 사라진다. 마커 클릭 시 상세는 `GET /api/v1/stop?pk=...`로 별도 조회한다.

### 4.6 Exposed `select` import 주의

`StopMapRepository`에서 `greaterEq` / `lessEq` 같은 비교 연산자는 `org.jetbrains.exposed.v1.core.*`에 있다. 개별 import(`core.and`만 등)로는 unresolved reference가 난다. 기존 `StopRepository`와 동일하게 와일드카드 import를 쓴다.

## 5. iam S2S 계약 — 기존 장애 발견 및 수정

### 발견된 문제

`StopInfo`의 좌표는 non-null `String` 생성자 파라미터 `xCrd`인데, stop 모듈이 실제로 보내는 필드명은 `xcrd`였다. jackson-module-kotlin은 생성자 파라미터명으로 매칭하므로 값을 찾지 못했다.

```
com.fasterxml.jackson.module.kotlin.KotlinInvalidNullException:
  Instantiation of [simple type, class com.media.bus.iam.client.stop.dto.StopInfo] value failed
  for JSON property xCrd due to missing (therefore NULL) value for creator parameter xCrd
  which is a non-nullable type
```

즉 `StopServiceClient`의 정류소 조회 계열(`getStopByPk`, `getStopByStopId`, `getStopByStopName`, `getStopsByPks`, `getStopPage`)이 **전부 실패하고 있었다.**

### 조치

`StopInfo`에 `@JsonAlias`를 추가해 두 이름을 모두 수용한다.

```kotlin
@JsonAlias("xcrd")
val xCrd: String,

@JsonAlias("ycrd")
val yCrd: String,
```

**이것은 롤링 배포 호환용이다.** 배포 도중에는 구버전 stop 인스턴스가 `xcrd`를, 신버전이 `xCrd`를 보낸다. 별칭이 없으면 배포가 완전히 끝날 때까지 일부 요청이 계속 실패한다. **구버전 인스턴스가 모두 교체된 뒤 제거 대상이다.**

### 외부 영향 (확인 필요 사항)

iam의 어드민 응답 `StopResponse`도 직렬화명을 고정했으므로, **어드민 API의 좌표 필드명이 `xcrd` → `xCrd`로 바뀐다.** 다만 위 장애로 해당 엔드포인트 자체가 실패하고 있었으므로 이 필드에 의존하는 소비자는 존재할 수 없다고 판단하고 진행했다. 별도 소비처가 발견되면 재검토할 것.

## 6. 신규 API

### `GET /api/v1/stop/map/bounds`

지도 현재 영역에 포함된 정류소 마커를 조회한다. 인가: `USER` / `BUSINESS` / `ADMIN`.

**요청 파라미터**

| 이름 | 타입 | 필수 | 설명 |
|------|------|------|------|
| `swLat` | string | O | 남서쪽 위도 |
| `swLng` | string | O | 남서쪽 경도 |
| `neLat` | string | O | 북동쪽 위도 |
| `neLng` | string | O | 북동쪽 경도 |
| `limit` | int | X | 반환 상한. 기본 1,000 / 최대 2,000. 0 이하는 기본값으로 보정 |

**응답**

```json
{
  "code": "00000",
  "message": "성공하였습니다.",
  "data": {
    "items": [
      { "id": "...", "stopId": "11833", "stopName": "중계역", "lat": 37.6472686, "lng": 127.0627647 }
    ],
    "truncated": false,
    "limit": 1000
  }
}
```

**설계 판단**

- **좌표를 `String`으로 받는다.** `BigDecimal`로 직접 바인딩하면 형식 오류가 스프링 바인딩 단계에서 터져 `ExceptionAdvisor`가 아닌 프레임워크 기본 메시지로 응답된다. `Coordinate` 검증을 거쳐 도메인 메시지로 400을 내리기 위함이다.
- **`level`(줌 레벨) 파라미터는 받지 않는다.** 서버 사이드 그리드 집계가 없어 동작에 영향이 없는데 스펙에 노출하면 프론트가 지원되는 기능으로 오해한다. 집계 도입 시 함께 추가한다.
- **잘림 판정은 COUNT 쿼리 없이** `limit + 1`건을 읽어 수행한다. 같은 범위를 두 번 스캔하지 않는다.
- **`(y_crd, x_crd)` 정렬을 고정**한다. 상한에 걸려 잘려도 매 요청 동일한 부분집합이 나온다. 정렬이 없으면 팬/줌마다 다른 마커가 나타났다 사라져 깜빡임처럼 보인다.
- 위도 조건을 먼저 두어 `idx_stop_coord`의 선행 컬럼을 태운다.
- **날짜변경선(antimeridian) 교차 미지원.** `swLng > neLng`는 400으로 거부한다. 지원하려면 경도 조건을 OR 두 구간으로 쪼개야 해서 인덱스 사용 계획이 달라진다.

### 변경된 기존 응답

`POST` 계열 일괄 등록 결과 `StopBulkRegisterResult`에 **`failedCount`가 추가**되었다. 좌표 불량 등으로 등록이 거부된 건수이며, "변경 없어 건너뜀"인 `skippedCount`와 의미가 다르다.

## 7. 모듈 분리를 하지 않은 이유

별도 `map` 모듈을 만들지 않고 `stop` 모듈 내 패키지로 격리했다. 후속 논의 시 근거를 재사용할 것.

1. **데이터 소유권이 `stop.stop`에 있다.** 모듈 경계 규칙상 타 모듈 Repository 직접 참조가 금지되므로 `map` 모듈은 bbox 조회를 `stop`에 S2S로 되물어야 한다. 지도는 `idle` 이벤트마다 호출되는 고빈도 API인데, 쿼리 한 방이면 끝날 일에 네트워크 왕복이 추가된다.
2. **독립 배포·스케일 근거가 없다.** 지도 조회 트래픽 = 정류소 읽기 트래픽이라 스케일 축이 같고, `stop`이 죽으면 `map`도 의미가 없어 장애 격리도 성립하지 않는다.
3. **운영 비용이 과하다.** 엔드포인트 1개를 위해 Gradle 모듈, `SecurityConfig`, Dockerfile, `docker-compose` 2벌, 게이트웨이 라우트, 포트, 헬스체크가 전부 늘어난다. AWS 기준으로 ECS 태스크/타깃그룹 고정비가 붙는다.

**재검토 트리거** — 아래 중 하나라도 해당하면 분리를 다시 논의할 가치가 있다.

1. PostGIS 도입 (`geometry` 타입 + `GIST` 인덱스)
2. 경로 조회 기능 확정 — 외부 API 호출·쿼터 관리·서킷브레이커가 붙고 장애 격리 근거가 처음 생긴다
3. 지도 데이터가 정류소를 넘어 노선/차고지/실시간 차량 위치까지 확장될 때
4. 줌 레벨별 그리드 집계를 Valkey에 사전 적재하는 배치성 워크로드가 생길 때

| 테스트 | 지키는 것 |

| `CoordinateTest` | scale 7 정규화, 범위 검증, 지수 표기 처리, `isSame`의 scale 무시 |
| `StopUpdateHistoryEntityTest` | 변경 감지 정확성. **표기만 다르고 값이 같으면 변경 아님**, 불량 좌표는 예외 |
| `StopMapRepositoryTest` (H2) | bbox 필터링, 경계값 포함, **자릿수가 달라도 숫자 비교**(`9.9` vs `10.1`), `limit+1` 조회, `lat`/`lng` 뒤바뀜 방지 |
| `StopMapQueryServiceTest` | `truncated` 판정과 초과분 절단 |
| `StopBoundsCriteriaTest` | 파라미터 검증(역전 범위, 날짜변경선, limit 보정) |
| `BusStopResponseSerializationTest` | 직렬화명이 `xCrd`/`yCrd`이고 `xcrd`/`ycrd`가 없을 것, 지수 표기 없음 |
| `StopInfoDeserializationTest` | 신·구 필드명 모두 역직렬화, `StopResponse` 직렬화명 |

`StopMapRepositoryTest`는 H2(PostgreSQL 모드) + Exposed `transaction {}` 기반이다. Spring 컨텍스트를 띄우지 않으므로 `@Transactional`은 무효이고, 테스트가 감싼 `transaction {}` 안에서 동작한다.

## 9. 배포 절차

1. **사전 점검** — 운영 DB에 파싱 불가 좌표가 있으면 `V004-1`이 `HALT`로 배포를 막는다. 미리 확인할 것.

   ```sql
   SELECT COUNT(*) FROM stop.stop
    WHERE TRIM(x_crd) !~ '^-?[0-9]+(\.[0-9]+)?$'
       OR TRIM(y_crd) !~ '^-?[0-9]+(\.[0-9]+)?$';
   ```

2. **iam 먼저 배포** — `@JsonAlias`가 있어 구·신 stop 응답을 모두 수용한다. 순서를 뒤집으면 배포 창 동안 조회가 계속 실패한다.
3. **stop 배포** — Liquibase가 `V004`를 적용한다. 좌표 컬럼 `ALTER TYPE`은 테이블 재작성을 유발하므로 11,000행 기준 짧지만 `ACCESS EXCLUSIVE` 락이 걸린다. 트래픽이 적은 시간대를 권장한다.
4. **정리** — 구버전 stop 인스턴스가 모두 교체된 뒤 `StopInfo`의 `@JsonAlias` 제거.
